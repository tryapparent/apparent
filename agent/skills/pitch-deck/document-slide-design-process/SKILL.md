# Document the slide design process

Keep a Markdown record for each slide. Use the project's format and brand rules. Update the record during the work with the baseline, choices, renders, and feedback.

## Discover and define

- Record the audience, presentation format, slide's role, brand reference, and baseline feedback. Inspect the existing frame when supplied.
- Give the slide one job. Write the five-second takeaway and intended reading order.
- Specify exact copy and its evidence. Give sources, units, timeframes, and qualifications. Flag any gaps.
- Choose the proof device before styling. Use a real screenshot for a product state, a chart for a relationship, or a diagram for a mechanism.

## Diverge with image-generated Crazy 8s

1. Generate eight full-frame directions with one image-generation call each. Hold the claim, evidence, aspect ratio, and brand rules fixed. Vary composition, focal point, reading path, and proof treatment.
2. Preserve each frame and prompt. Inspect all eight in a labeled, equal-scale contact sheet with access to full-size frames. Replace palette swaps and near-duplicates.
3. Record one strength, one trade-off, and any evidence problem per direction. Reject invented claims, duplicated metrics, and missing qualifications that undermine the layout. Correct minor generated typography errors in the editable slide.
4. Compare promising directions with the adjacent slides. Review alternatives with the user if a design choice is needed. Record which direction was selected and why.

## Refine and verify

- Refine the chosen direction once with image generation. Preserve its major visual regions and reading order while improving hierarchy, crop, and the connection between claim and proof.
- Rebuild in the deck's editable format using exact copy, actual fonts, and approved assets. Compare the rendered slide with the selected concept.
- Inspect it at presentation size and in the deck contact sheet. Check font family, weight, and size against the brand guide, then contrast, color roles, hierarchy, spacing, clipping, and the five-second takeaway. Verify navigation and links if changed.
- Fix observed issues and re-render. Reopen Crazy 8s for a structural reset. For a focused correction, compare the before and after at the same scale. Inspect marked frames before acting on a critique captured with Apparent.
- Record technical results and design findings separately. Reserve acceptance for explicit user approval.

Use these headings in the slide record: **Baseline and sources**, **Takeaway and proof**, **Crazy 8s and decision**, **Refinement and render**, **Checks**, **Feedback and status**. Link the frames, comparison sheet, and editable implementation.

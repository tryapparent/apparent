# Paired stable application publication

`Release application` reuses `.github/workflows/verification.yml` to stay within the workflow directory budget. Its default `mode=verify` dispatch retains the manual Linux verification wrapper. Stable assembly is distinct from ordinary Linux/shared verification and independent Linux Main and Mac preview publication.

The coordinator admits an exact main ancestor with the existing Linux/shared receipt and a numeric Cargo package version newer than the last public stable release. An explicit `mode=stable` dispatch accepts the parent-supplied exact source, or selects the newest eligible verified main source. Normal PR/main checks never activate stable publication. Eligibility compares against the last successful stable version, so unrelated main changes cannot erase a pending version. A version bump is the stable delivery signal; a previously published version is never rebuilt as another stable release. A selected source can differ from the control SHA. The resolved candidate SHA/version/tag are explicit admission outputs and appear in the immutable manifests and release body; the run title's triggering SHA is only a hint.

Linux configuration/readiness and both native AppImage packaging gates precede Mac allocation. The Mac adapter prepares portable frontend output on Linux, then performs native assembly, signing, notarization and focused installation checks on one Apple-silicon host. Full native capture suites remain manual. Both architectures/platforms share one `vX.Y.Z` release and source SHA. The fork's Mac Preview bundle identity, signing credentials and preview Sparkle channel remain in use; stable visibility does not migrate app identity or OS registrations.

Each immutable candidate artifact is named `stable-PLATFORM-ARCH-ATTEMPT`, contains final bytes and `manifest-PLATFORM-ARCH.json`, and expires under Actions retention. The manifest binds source, numeric version, stable distribution channel, tag, repository, actual producer run/attempt, workflow control SHA, native/signing evidence and exact filename/size/SHA-256 tuples. Publication verifies authenticated producer jobs for that attempt, API artifact identity and archive digest, archive paths and extracted payload/sidecar digests. An artifact name alone never admits publication.

Publication serializes across candidates with `cancel-in-progress: false`: a running publication finishes and GitHub coalesces pending dispatches. No public release or moved tag is overwritten. All final bytes upload to a draft before it becomes public; missing either platform leaves it private. A partial draft retry uploads only missing assets and refuses differing existing bytes. A completed release retry accepts only identical candidate/provenance/bytes. Newer public stable versions block older candidates from becoming latest.

For a publication-only retry, dispatch with `candidate_run_id` and its exact `candidate_attempt`, leaving `source_sha` empty. These inputs skip Linux and Mac builds. Successful build jobs remain required even if publication failed; the entire producer workflow need not have succeeded. Missing, expired or altered candidate artifacts fail closed and need a new build; they are not silently recreated. Failed publication/distribution jobs retain the original admitted producer-attempt output, so their normal failed-job retries reuse exact artifacts. `mode=distribution` with the original run/attempt retries feed and cask without repeating GitHub publication. The jobs are separate and can also be retried independently. Rerunning a whole workflow creates a distinct attempt; it cannot masquerade as the old attempt's bytes.

Independent previews keep their existing channels. Linux Stable discovers non-prerelease semver tags; Main keeps `linux-main-v2-SHA`. Public's existing newest-asset download selector still includes previews: this change does not claim stable-only website distribution, change its UI, or migrate installed Mac preview identity. Feed and tap updates occur after GitHub visibility and have separate retry/failure boundaries; no cross-service atomicity is claimed.

Run `node --experimental-strip-types --test composition/enablement/release/*.test.ts composition/enablement/release/test/*.test.ts`. Tests exercise actual ZIP restore commands with authenticated-response fixtures, producer/job/attempt trust, final byte corruption, incomplete pairs and immutable release asset rules. They do not prove hosted signing, installation, publication permissions or live update behavior. Activation and native hosted proof remain release-owner actions.

Routing rollback retains Main/preview paths; do not restore the retired independent Linux stable attachment job. The remaining frozen packaging donors stay authoritative until their own adapters and real platform consumers are migrated and accepted.

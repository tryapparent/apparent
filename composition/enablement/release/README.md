# Desktop installer publication

**Latest Main** (`mode=main` in `.github/workflows/verification.yml`) publishes both AppImages together under `linux-main-v2-SHA` and the signed, notarized Apple-silicon Nightly DMG and ZIP separately under `mac-nightly-v2-SHA`. Each prerelease uses the exact verified source and is published when its own artifact set is complete. A Mac runner or signing failure leaves Linux publication eligible. Existing Linux installs discover the same tag family.

Mac Nightly discovers updates via `nightly.xml` on the fork's feed branch. The feed job verifies the exact published bytes and can retry by producer run and attempt. Stable Sparkle discovery and Homebrew use `appcast.xml`. The on-demand `mode=mac-main` exact-source test build still publishes only its immutable `mac-main-v2-SHA` assets.

Stable admission requires an exact main ancestor with the existing Linux/shared receipt and a numeric Cargo package version newer than the last public stable release. An explicit `mode=stable` dispatch accepts the parent-supplied exact source, or selects the newest eligible verified main source. Normal PR/main checks never activate stable publication. Eligibility compares against the last successful stable version, so unrelated main changes cannot erase a pending version. A version bump is the stable delivery signal; a previously published version is never rebuilt as another stable release. A selected source can differ from the control SHA. The resolved candidate SHA/version/tag are explicit admission outputs and appear in the immutable manifests and release body; the run title's triggering SHA is only a hint.

All Stable artifacts share one `vX.Y.Z` release and source SHA. Both Linux architectures and the Mac lane build in parallel after shared admission. The fork's Mac Preview bundle identity, signing credentials and preview Sparkle channel remain in use. Full native capture suites remain manual.

The Linux packaging workflow receives the coordinator's admitted CI run ID and attempt. It rechecks that exact receipt and current attempt without listing runs. Regular release admission resolves live canonical `refs/heads/main` over Git and proves ancestry in the full-history checkout. If local objects prevent the proof, it tries one bounded fetch of that resolved SHA from canonical GitHub and repeats the proof against the same SHA. The fetch leaves the checkout, index, refs and `FETCH_HEAD` untouched. Shallow history, inaccessible required objects, divergence and a moved verification attempt stop admission. Publication keeps its separate receipt and ancestry checks.

Main dispatch and packaging each serialize with one replaceable pending run. Automatic dispatch coalesces duplicates and older sources against queued and active verified Main requests. Admission can retire an older candidate before allocation when a newer verified request is already queued. Started Linux builds can finish. Stable admission pins its source and version independently of the Main queue.

Mac Main and Stable both prepare frontend output on Linux, then run the ARM, SDK, signing, notarization and install gates on the selected Mac image. `macos-26` is the default, with `macos-15` as the fallback. Both use Xcode 26.3. Manual dispatch can reverse the order or select `xcode-27` as primary with Xcode 27.2 and `macos-26` as its fallback. A fallback runs only after GitHub confirms the primary job was cancelled without a runner. It reuses the frontend output and the same producer attempt, so Stable Linux artifacts remain available. The Mac summary reports assignment waits when GitHub provides timing metadata.

Each immutable candidate artifact is named `stable-PLATFORM-ARCH-ATTEMPT`, contains final bytes and `manifest-PLATFORM-ARCH.json`, and expires under Actions retention. The manifest binds source, numeric version, channel, tag, repository, actual producer run/attempt, workflow control SHA, native/signing evidence and exact filename/size/SHA-256 tuples. Publication checks the jobs and artifacts required by that channel, validates archive identity and digest, and checks extracted payload and sidecar digests.

Publication serializes by channel. All required final bytes upload to a draft before it becomes public. A partial draft retry uploads only missing assets and refuses differing existing bytes. A completed release retry accepts only identical candidate provenance and bytes. Newer public Stable versions block older Stable candidates from becoming latest. A published Linux Main descendant blocks promotion of an older Linux Main source.

The **Desktop release outcome** summary reports Linux Main and Mac Nightly separately. It verifies public links by anonymous range requests. For publication-only retries use `linux-main`, `mac-nightly`, or `paired-main` for historical combined candidates, with the original run and attempt.

For a publication-only retry, dispatch in the original channel with `candidate_run_id` and its exact `candidate_attempt`, leaving `source_sha` empty. These inputs skip Linux and Mac builds. Successful build jobs remain required even if publication failed; the entire producer workflow need not have succeeded. Missing, expired or altered candidate artifacts fail closed and need a new build; they are not silently recreated. Failed publication/distribution jobs retain the original admitted producer-attempt output, so their normal failed-job retries reuse exact artifacts. `mode=distribution` with the original run/attempt retries feed and cask without repeating GitHub publication. The jobs are separate and can also be retried independently. Rerunning a whole workflow creates a distinct attempt; it cannot masquerade as the old attempt's bytes.

Linux Stable discovers non-prerelease semver tags. Older Linux-only Main releases retain their existing assets. Public's existing newest-asset download selector still includes previews: this change does not claim stable-only website distribution, change its UI, or migrate installed Mac preview identity. Feed and tap updates occur after GitHub visibility and have separate retry/failure boundaries; no cross-service atomicity is claimed.

Run `node --experimental-strip-types --test composition/enablement/release/*.test.ts composition/enablement/release/test/*.test.ts`. Tests exercise actual ZIP restore commands with authenticated-response fixtures, producer/job/attempt trust, final byte corruption, incomplete pairs and immutable release asset rules. They do not prove hosted signing, installation, publication permissions or live update behavior. Activation and native hosted proof remain release-owner actions.

The existing manual Mac preview workflow remains a recovery path. The frozen packaging donors remain authoritative for their existing adapters and platform consumers.

## Amazon Linux CLI

Linux Main and Stable also publish an `Apparent-CLI-VERSION-amazon-linux-2023-x86_64.zip` and checksum from the x86-64 candidate. It builds the same `apparent` command against glibc 2.34 and inspects an annotated bundle from the candidate AppImage in a clean Amazon Linux 2023 container before sealing. The ZIP is for headless reading. Use the AppImage for desktop capture and bundled media plugins. Sources predating the CLI builder retain their historical payloads.

Download the ZIP and its `.sha256` from the same release. Run `sha256sum -c <archive>.sha256`, then `unzip <archive>` in a fresh directory. Run `./apparent-cli/apparent inspect ./capture.apparent`, and keep the binary beside its `lib/` directory. Fetching a hosted capture still requires outbound HTTPS and read approval.

On an x86-64 Linux machine with Docker, reproduce the build from the repository root with `node --experimental-strip-types composition/enablement/release/amazon-linux-cli/build.ts /path/to/output /path/to/producer.AppImage`.

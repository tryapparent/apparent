# Paired application publication

**Release** (`.github/workflows/verification.yml`) publishes one release containing both Linux AppImages and the signed, notarized Apple-silicon Mac DMG and ZIP. Successful Main CI dispatches it with the exact verified source and CI run ID, then finishes independently. Linux x86_64, Linux aarch64 and the Mac lane start after shared admission. The Mac lane prepares portable frontend output on Linux before allocating one ARM Mac for assembly, signing, notarization and installation checks. GitHub publication waits for all three packages.

Run it manually from `main` with `gh workflow run verification.yml --repo tryapparent/apparent --ref main -f mode=main -f source_sha=FULL_SHA`. Main is the default mode and publishes an immutable `linux-main-v2-SHA` prerelease using the Cargo version at that SHA. It preserves installed Linux Main discovery and offers Mac packages through GitHub Releases. The versioned Sparkle feed and Homebrew tap advance through stable or the existing manual Mac preview path.

Stable admission requires an exact main ancestor with the existing Linux/shared receipt and a numeric Cargo package version newer than the last public stable release. An explicit `mode=stable` dispatch accepts the parent-supplied exact source, or selects the newest eligible verified main source. Normal PR/main checks never activate stable publication. Eligibility compares against the last successful stable version, so unrelated main changes cannot erase a pending version. A version bump is the stable delivery signal; a previously published version is never rebuilt as another stable release. A selected source can differ from the control SHA. The resolved candidate SHA/version/tag are explicit admission outputs and appear in the immutable manifests and release body; the run title's triggering SHA is only a hint.

Full native capture suites remain manual. All stable artifacts share one `vX.Y.Z` release and source SHA. The fork's Mac Preview bundle identity, signing credentials and preview Sparkle channel remain in use; stable visibility does not migrate app identity or OS registrations.

Both channels retain the existing candidate artifact naming for retry compatibility. Each immutable candidate artifact is named `stable-PLATFORM-ARCH-ATTEMPT`, contains final bytes and `manifest-PLATFORM-ARCH.json`, and expires under Actions retention. The manifest binds source, numeric version, Main or stable channel, tag, repository, actual producer run/attempt, workflow control SHA, native/signing evidence and exact filename/size/SHA-256 tuples. Publication verifies authenticated producer jobs for that attempt, API artifact identity and archive digest, archive paths and extracted payload/sidecar digests. An artifact name alone never admits publication.

Publication serializes across candidates with `cancel-in-progress: false`: a running publication finishes and GitHub coalesces pending dispatches. No public release or moved tag is overwritten. All final bytes upload to a draft before it becomes public; missing either platform leaves it private. A partial draft retry uploads only missing assets and refuses differing existing bytes. A completed release retry accepts only identical candidate/provenance/bytes. Newer public stable versions block older stable candidates from becoming latest. A published Main descendant blocks promotion of an older Main source.

The **Paired release outcome** step summary reports the source and the publication result. **Published** links to the AppImages, DMG and ZIP after anonymous range requests confirm that public downloads respond with the expected asset sizes. **Superseded** identifies the newer Main tip that changed the installer inputs or the newer public release that prevented publication. **Failed** points to the relevant admission, producer, publication or download check. A public download check runs after publication and cannot roll back a release or gate stable feed and tap jobs. If a producer retry fails before its manifests can be verified, the summary identifies the attempted producer run and attempt. Stable admission with no eligible version has its own outcome.

For a publication-only retry, dispatch in the original channel with `candidate_run_id` and its exact `candidate_attempt`, leaving `source_sha` empty. These inputs skip Linux and Mac builds. Successful build jobs remain required even if publication failed; the entire producer workflow need not have succeeded. Missing, expired or altered candidate artifacts fail closed and need a new build; they are not silently recreated. Failed publication/distribution jobs retain the original admitted producer-attempt output, so their normal failed-job retries reuse exact artifacts. `mode=distribution` with the original run/attempt retries feed and cask without repeating GitHub publication. The jobs are separate and can also be retried independently. Rerunning a whole workflow creates a distinct attempt; it cannot masquerade as the old attempt's bytes.

Linux Stable discovers non-prerelease semver tags. Older Linux-only Main releases retain their existing assets. Public's existing newest-asset download selector still includes previews: this change does not claim stable-only website distribution, change its UI, or migrate installed Mac preview identity. Feed and tap updates occur after GitHub visibility and have separate retry/failure boundaries; no cross-service atomicity is claimed.

Run `node --experimental-strip-types --test composition/enablement/release/*.test.ts composition/enablement/release/test/*.test.ts`. Tests exercise actual ZIP restore commands with authenticated-response fixtures, producer/job/attempt trust, final byte corruption, incomplete pairs and immutable release asset rules. They do not prove hosted signing, installation, publication permissions or live update behavior. Activation and native hosted proof remain release-owner actions.

Reverting this routing change restores separate Linux Main publication. The stable coordinator and manual Mac preview remain available as recovery paths. The frozen Linux Main publisher and its legacy tests remain in the root build inventory for that rollback. The remaining frozen packaging donors stay authoritative until their own adapters and real platform consumers are migrated and accepted.

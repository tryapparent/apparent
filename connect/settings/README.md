# Connect account Settings

The installed General pane composes the Connect card. Settings and onboarding
use one TypeScript socket host. The native window fallback uses the same
presentation through the installed Electron Node runtime and caches each
distinct input. Version-matched desktop packages use typed account facts.
The host also reads the previous native view format for existing development
providers. Deploy the native and Electron halves together when rolling back.

Bend selects the account status, copy and recovery from local grant validity,
access expiry, operation receipts and transport outcomes. The host projects
only the documented fields into the renderer. The only device approval data
in that view is the validated human-facing code and verification URI. Browser
opening still requires a matching action on the current native session.

The native client retains credential and encryption material, consent
publication, renewal locks and journals, and upload admission. A status card
never grants access. Local reads do not renew access. An explicit connection
check can renew through the existing native provider. An open Settings window
checks a saved connection on its first General visit and keeps the last status
visible on return while it reads local facts. Polling pauses outside General.
The Connect account menu keeps the manual check available.

`apparent connect status` and `apparent connect readers` retain their existing
machine-readable diagnostic fields, including renewal deadlines and CLI
reapproval guidance. The standalone Amazon Linux CLI has no packaged JavaScript
runtime. `status --account` remains the explicit user-requested network check.

Run `node connect/enablement/ci/local/settings.ts` with Node 22 for the
standalone Connect host and model tests. The Compose Settings Electron smoke
can use the staged application and runtime with `APPARENT_CONNECT_STAGE`.
That also compares the packaged fallback process and Electron host projection.

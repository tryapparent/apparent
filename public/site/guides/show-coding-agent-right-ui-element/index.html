How to show a coding agent which UI element you mean

If your coding agent keeps changing the wrong thing on screen, show it the section, the control label, and the behavior you expect. For a visible web element, select it in the agent’s browser. If it disappears before you can select it, record the steps leading up to the bug.

Choose what to show the agent

  • A control you can select in the browser

    Use the agent’s browser annotation to attach your request to the exact control. Codex’s built-in browser lets you select an element or region. Cursor Design Mode includes the screenshot and element context.

  • A control you can show in one screenshot

    Circle it and keep the section heading and nearby controls visible. A screenshot works for a native app too. Include how to reach that screen and what you want to happen.

  • A control that disappears or changes while you interact

    Record the lead-up and the result. For example, a click on File actions opens a menu that closes while the pointer is moving toward Rename. The last screenshot shows the closed menu. The recording shows the open menu, pointer movement, and when the menu disappears.

    With Apparent, say what you expected as you point. Your agent can inspect the transcript and frames around the moment the target disappears. Watch the simulated Rename-menu bug or record your own example.

Check that the agent found the right control

If two buttons say Save, name the section and the nearby control you want to preserve. Give the agent a way to verify each one separately.

In Profile, disable Save until the display name changes. Keep Notifications → Save available. Before editing, identify what renders the Profile button. After editing, check both buttons separately.

If both buttons use a shared component, ask the agent to identify the call site or condition that distinguishes the two instances before it edits the component.
